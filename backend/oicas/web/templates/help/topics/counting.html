Record what was physically counted. A count session is one counter on one date. It contains entries, and each entry is one counted figure for one item at one location.

Session life cycle

{{ pill('draft') }} → {{ pill('submitted') }} → {{ pill('finalized') }} (or {{ pill('cancelled') }})

DraftThe counter adds and removes entries freely.
SubmittedEntries are locked. They can only be corrected by a manager, who gives a new quantity and a reason; the original stays in history.
FinalizedA manager finalizes. OICAS compares the counts with the latest Odoo snapshot (or book balance) and creates the reconciliation results.
CancelledDraft or submitted sessions can be cancelled with a reason.

Option A — enter counts on screen

  1. Physical Counting → Start a count session: count date (not in the future), counted by, optional plan, remarks → Start session.
  2. For each figure: type the RM code (suggestions appear after 2 letters), choose Location (Warehouse / Production), Slot (1–4 = WH-1…4 or PROD-1…4), Round, Quantity and optional remarks → Add.
  3. Check the list, then Submit.
  4. Manager: Finalize & reconcile. The results appear under Reconciliation results, each with a Review button.

Option B — upload a filled count sheet

  1. Download the sheet from the plan (Count sheet (Excel)). Fill B2 = count date, B3 = counted by, and the quantities per column.
  2. Physical Counting → Upload a filled count sheet → Upload as draft. Errors (unknown code, text in a quantity, negative number) are listed and nothing is saved.
  3. Review the draft, then Submit and Finalize as above.

For many dates or counters in one file, use Data Import → Count lines.

Rules to remember

  • Blank = not counted. Enter 0 only if you counted and found nothing.
  • Several entries for the same item, location and date are added together (e.g. WH-1 = 60 and WH-2 = 40 → warehouse total 100), just like COUNTED LIST.
  • Pressing a button twice doesn't create duplicates.
  • If the Odoo data is older than allowed (default 24 h), finalizing asks you to tick finalize against stale Odoo data. It's better to Sync Odoo now first.
Example
Session #36, 2026-10-20, Christine A: 8RM04-341-1 Warehouse slot 1 = 220.4; 1SH03-001 Warehouse slot 1 = 2,400 → Submit → manager Finalize against Odoo snapshot #41 → 8RM04-341-1: 220.4 vs 220.4 → {{ pill('accurate') }}; 1SH03-001: 2,400 vs 2,403 → variance −3 {{ pill('discrepancy') }}.

Correcting a submitted count

On the session page (manager): type the new qty and the reason on the entry's row → Correct. The old entry is struck through, the new one is added, and if the session was already finalized, the reconciliation is recalculated.
