Some data isn't in Odoo: items not encoded yet or without a code, their expected stock, counts from other sources, and consumption recorded elsewhere. Data Import loads it from Excel using fixed templates. Odoo itself is never changed.

How every import works

  1. Press Template to download the Excel file. Its DATA sheet has the exact columns and a grey example row, and the HOW TO sheet explains each column.
  2. Fill the DATA sheet. You can leave the grey example row unchanged (it's ignored) or overwrite it.
  3. Choose the file and press Dry run. OICAS checks every row and shows what would be created or updated, without saving anything.
  4. If it's valid, press Import. It's all-or-nothing: one bad row means nothing is saved, and each error is listed with its row number.
  5. The result is logged in Import history and the Audit Trail.

1. Items not in Odoo

Columns: RM CODE · DESCRIPTION · UOM · MATERIAL SECTION · ABC FAMILY · PLANT LOCATION · REMARK · TRACKED.

  • No code yet? Leave RM CODE blank and OICAS gives a temporary code: NC-00001, NC-00002…
  • Existing codes are updated: section, family, plant, remark and tracked. For items that exist in Odoo, the description and UoM stay as in Odoo.
  • PLANT LOCATION must be one of 1, 2, 3, 4, 1 & 2, 1 & 3, … and ABC FAMILY one of the configured families.
  • TRACKED = yes puts the item in the masterlist and schedule.
Example
Row: (blank) · Gasket - silicone 5mm · Piece · Consumables · Excluded list · 3 · · yes → creates NC-00001, tracked, plant 3, listed in Data Quality as not in odoo.

2. Book balances

Columns: BALANCE DATE · RM CODE · WAREHOUSE · PRODUCTION · REMARKS. This is the expected (system) stock of items Odoo doesn't hold, e.g. from a stock card.

  • Used by reconciliation only when Odoo has no balance for the item, and only a balance dated on or before the count date.
  • Blank WAREHOUSE or PRODUCTION means unknown, not 0.
  • Counts that had no balance before are re-checked automatically after the import.
Example
Book balance 2026-10-20 · NC-00001 · WAREHOUSE 120. Christine counts 118 → variance −2, and the reconciliation shows System balance from: imported book balance.

3. Count lines

Columns: DATE COUNTED · RM CODE · COUNTED BY · COUNT (WH-1…4) · COUNT (PROD-1…4) · REMARKS · BOOK WH · BOOK PROD. The same layout as the old COUNTED LIST.

  • Rows are grouped into one session per date + counter, created as submitted; a manager finalizes them in Physical Counting.
  • A row with no quantity at all is skipped and reported, because a blank isn't a count.
  • The optional BOOK WH / BOOK PROD columns save book balances for that date at the same time.

4. Demand / consumption

Columns: Components/Created on · Components/Product/Reference · Components/Product/Name · Components/Demand, the same as the Odoo export behind the old Demand sheet. Rows are summed per item and month into a demand batch. Then go to AMC Analysis and calculate a new run with that batch.

When the item is finally encoded in Odoo

Open the item → Change item code → enter the Odoo Internal Reference. All counts, reconciliations, demand and plans move to the new code, and the next Sync Odoo now links it to the Odoo product (its Odoo balance is used from then on).

Other loaders

  • Count sheet from a plan: Cycle Count Planning → plan → Upload the filled count sheet.
  • Legacy Excel migration (one time, admin): System Configuration → Imports → Migrate legacy workbooks.
  • Stock from Odoo: Loading from Odoo.
